VidFlow System Architecture

Hybrid API Connectivity & OAuth Strategy

DOKUMEN RAHASIA

Juni 2026

Dokumen ini menguraikan keputusan arsitektur teknis di balik sistem integrasi OAuth pada VidFlow. Sistem didesain menggunakan pendekatan "Hybrid" guna memaksimalkan skalabilitas server (menghindari limitasi kuota API) sekaligus mempertahankan kemudahan penggunaan bagi pelanggan akhir (UX).

1. Ekosistem Google (YouTube) & Meta (IG/FB)

Pada ekosistem YouTube, Facebook, dan Instagram, VidFlow menerapkan sistem BYOK (Bring Your Own Key). Pelanggan diwajibkan untuk membuat aplikasi di Google Cloud/Meta Developer dan memasukkan Client ID & Secret mereka sendiri ke dalam database VidFlow.

Masalah Kuota Ekstrem (Alasan BYOK Diterapkan)

Google menerapkan batasan yang sangat ketat untuk aplikasi pihak ketiga (SaaS). Secara default, satu aplikasi Google hanya diberikan 10.000 Unit Kuota per hari. Biaya untuk mengunggah 1 (satu) video ke YouTube adalah 1.600 Unit.

Artinya, jika VidFlow menggunakan API Key terpusat (dari `.env`), aplikasi kita hanya mampu mengunggah 6 video per hari secara global. Begitu user ke-7 mencoba mengunggah, seluruh server akan terkena blokir Rate Limit Exceeded.

Solusi & Keuntungan Skalabilitas Tak Terbatas

Dengan memaksa user memasukkan API Key mereka sendiri (BYOK), batas limit tersebut dialihkan sepenuhnya ke Google Cloud milik masing-masing user. Jika Anda memiliki 10.000 pelanggan, maka ada 10.000 API Key berbeda yang bekerja secara paralel. Server VidFlow memiliki Skalabilitas Tanpa Batas (Infinite Scalability) dan bebas dari risiko tagihan API maupun pemblokiran kuota dari Google/Meta.

2. Ekosistem TikTok (Direct Post API)

Berbeda 180 derajat dengan YouTube/Meta, integrasi TikTok pada VidFlow menggunakan Kredensial Master (Centralized API). Semua user akan melakukan otentikasi menggunakan satu Client ID dan Client Secret yang ditanam di dalam file .env server VidFlow.

Kompleksitas Registrasi (Alasan Kredensial Master)

Pendaftaran aplikasi di portal TikTok for Developers menuntut proses yang sangat kompleks, seringkali membutuhkan verifikasi entitas bisnis/perusahaan dan peninjauan manual yang ketat. Mustahil untuk meminta pelanggan awam melakukan proses ini. Jika model BYOK diterapkan pada TikTok, VidFlow akan kehilangan 99% pengguna karena tingkat kesulitan konfigurasi.

Infrastruktur Kuota TikTok yang Aman untuk SaaS

Beruntungnya, TikTok tidak memberlakukan kuota global sempit seperti Google. Dalam sistem TikTok:

  • Limit unggahan dibatasi Per Akun Kreator (User Token), yaitu maksimal 15 video/hari. Ini dihitung pada sisi akun pengguna, bukan aplikasi pembuatnya.
  • Satu Master App VidFlow mampu menampung puluhan ribu Access Token user secara independen tanpa saling bertabrakan kuotanya.
  • Hal ini memungkinkan VidFlow menghadirkan pengalaman pengguna (UX) "1-Click Connect" untuk TikTok yang sangat mulus tanpa khawatir server terkena limitasi jumlah video harian.

3. Kesimpulan Arsitektur (Hybrid Defense)

Struktur yang saat ini tertanam di dalam PlatformConnectionController.php adalah sebuah desain sistem SaaS yang sudah mempertimbangkan ketahanan server jangka panjang. Dengan menggabungkan pertahanan BYOK (YouTube/Meta) untuk menghindari Rate Limits, dan Centralized OAuth (TikTok) untuk mempertahankan retensi pengguna, VidFlow memiliki fondasi yang siap menampung ribuan pengguna aktif berbayar secara bersamaan.
